# HANDOFF — landing-pages

**Updated:** 2026-07-30 · **Repo:** https://github.com/AdbitRush/landing-pages · **Branch:** main

The **public delivery surface** for advertorials. It holds no logic: pages are
generated by Abri Brain / ABRi-Qwe CMS and deployed here to get a real URL that ads
can point at.

---

## Where it runs

| | |
|---|---|
| **Live** | https://adbitrush.github.io/landing-pages/ — GitHub Pages, branch `main` |
| Index | `index.html` — "Abri Landing Pages", links the published pages |
| Pages | `lp/<slug>/` — one folder per advertorial |
| Generated by | ABRi-Qwe CMS `:8772/landing` (the hub's card links straight to it) |
| In the hub | ABRI ONE → Ads engine → Landing Pages |

Deploy = `git push`. Live in about a minute.

## Notes

- **Anything pushed here is public and indexable.** It's an ad-landing host, so
  that's the point — but it means no client names, no internal numbers, no test
  copy you wouldn't want found. Once Google has it, a delete doesn't un-index it.
- Slugs are the ad's destination URL. **Renaming or removing a folder breaks live
  ads silently** — the campaign keeps spending into a 404. Add new slugs; retire
  old ones only after the campaign is off.
- No build step, no CI. What's in the repo is what's served.
